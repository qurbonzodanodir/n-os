# n-os

A bilingual personal workspace with a Liquid Glass inspired interface. Public source code; the hosted workspace remains owner-private. No personal sample records or credentials are included in this repository.

## Architecture migration

The production rewrite now lives in two independent applications:

- `frontend/` — React, TypeScript and Vite.
- `backend/` — Python, FastAPI, SQLAlchemy and Alembic.

The original JavaScript application remains runnable at the repository root
until feature parity is complete. See `docs/MIGRATION.md` for the migration
order and safety boundary.

Run the new applications in separate terminals:

```sh
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
uvicorn app.main:app --reload
```

```sh
cd frontend
npm install
npm run dev
```

For a production-like PostgreSQL deployment, create `.env` from `.env.example`
and run `docker compose up --build`. The frontend is served on port 8080 by
default and proxies `/api` to FastAPI. Production must provide the trusted
authenticated-user header at the edge; development identity headers are
disabled in production mode.

## Run the legacy application locally

Requires Node.js 24 or newer.

```sh
npm ci
npm start
```

Open http://localhost:4173. The development server uses SQLite in the ignored `.local/` directory and a fixed **local-only** identity. Do not expose this development server to the internet. The production Worker requires an authenticated identity provided by Sites.

```sh
npm test
npm run build
```

## Implemented

- Today hub with real current dates, tasks, events and habit progress.
- Tasks: list/board, status, priorities, subtasks, recurrence and overdue filtering.
- Calendar: month, week, day and agenda; recurring events and linked tasks.
- Habits: dated check-ins, selected weekdays, calculated streaks.
- Notes: plain Markdown editor and safe preview, folders, tags, pinning and archive.
- Projects and goals: linked records, milestones and calculated task progress.
- Finance: currency-specific accounts, income, expenses, same-currency transfers and category budgets. Money is stored as integer minor units.
- Weekly review calculated from dated records, plus written reflections.
- Russian and English interface, light/dark/system themes, reduced transparency.
- Server persistence with owner isolation and optimistic revision checks.
- JSON export/import and migration of the original browser-local prototype.

## Deployment architecture

This iteration preserves the existing small JavaScript frontend and packages it with a Cloudflare-compatible Worker and Sites D1 storage. A bounded workspace document is stored per authenticated owner. Concurrent edits never silently replace a newer revision. The production schema is generated by Drizzle and applied through Sites migrations.

This is **not yet** the Next.js + FastAPI + PostgreSQL production architecture described in the original product plan. See `docs/ARCHITECTURE.md` for the migration boundary. There is no app-owned registration/password system, background push/email delivery, AI, bank integration or full offline mode in this release.

The public GitHub snapshot excludes uploaded reference documents, earlier personal seed data, local databases, deployment credentials and the private Sites project ID. Copy `.openai/hosting.example.json` to `.openai/hosting.json` and supply your own project identity when deploying an independent copy. Local build can also use the example manifest.

## Data safety

Export before importing a replacement workspace. Legacy habit arrays do not contain reliable dates; migration preserves the legacy slots but does not invent completion history. Existing browser-local data stays intact. Saving failures retain edits on screen. A revision conflict offers export and explicit reload rather than overwriting the other device.
