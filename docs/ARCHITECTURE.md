# Architecture and deployment boundary

## Current working release

`app.js` composes views and forms. `src/domain.js` owns recurrence, dated statistics, integer money calculations, migration and validation. `src/i18n.js` holds paired interface dictionaries. `src/store.js` owns the HTTP persistence boundary. `src/api-worker.js` handles authentication, same-origin writes, validation and versioned storage. Icons and all styling are local assets; no remote fonts or trackers are required.

Cloudflare-compatible build output embeds the frontend assets in an ES module Worker exporting `fetch`. Sites dispatch owns sign-in and owner-only access. The API trusts only the dispatch-provided authenticated-user ID on the hosted platform; clients cannot select an owner in the request body. Every query is scoped to that owner. The local Node server injects a development identity only for local development and is not the production entry point.

D1 has one `workspaces` row per owner containing a schema-versioned JSON document. Prepared statements and a revision comparison implement atomic optimistic concurrency. The document is bounded at 1.5 MB and each collection at 3,000 records. This approach suits a personal prototype; large histories need normalized tables and pagination. Schema migrations are generated by Drizzle and deployed with the build.

## Target from the original architecture plan

Next.js/React/TypeScript frontend → FastAPI `/api/v1` → service layer → repositories → PostgreSQL. Alembic manages migrations. Redis/Celery handles deferred work. Docker Compose, Nginx and CI support a separate production deployment. This stack is a future migration, not silently replaced by the Sites prototype.

The current store boundary permits replacing document persistence with resource APIs. Before migration, define API contracts and normalize tasks, events, completions, notes, projects, goals, accounts, transactions and budgets with ownership foreign keys. Import existing JSON exports transactionally, preserve IDs and verify totals. Do not move personal data into Git history.

## Limitations

Event times are local wall times in one workspace timezone. No per-occurrence exceptions, DST-disambiguation UI or external calendars yet. Reminder delivery is in-app only. JSON export is user-triggered; a scheduled database backup and tested restore pipeline remain production work. The local prototype migration cannot recover historical completion dates that were never recorded.
